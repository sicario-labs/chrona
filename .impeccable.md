# Chrona Console — Design Context

## Product
Chrona is a documentation hosting platform for developers and AI agents. Core promise: **"Docs that can't go stale"** — every deployed claim is verified against the real codebase (Truth Referee), so the docs you serve are provably current. This console is the management surface for that product: projects, deploys, domains, env, analytics, billing, team.

## Target audience
Developers and docs maintainers (solo devs, small platform/API teams, agent-first engineers). They are technical, impatient, allergic to fluff, and they copy-paste commands. They judge a dev tool by density and precision, not decoration.

## Jobs to be done
- Create a docs project and get a live URL in minutes
- Deploy from the CLI (local build + edge sync) and watch it go live in seconds
- Understand what is live, what was superseded, what failed — and roll back instantly
- Attach a custom domain with clear DNS steps
- Manage env vars, API keys, team access
- See human vs agent traffic on their docs
- Trust the numbers (the whole point: verified truth, no drift)

## Brand personality / tone
**Calm, precise, confident — a precision instrument, not a fireworks show.** Think Linear/Vercel/Stripe/Resend: developer-first, short sentences, status as verdicts, restraint over decoration. The interface should feel like it is *telling the truth* — exact numbers, exact states, no marketing copy. Emotion lives in the correctness of the detail, not in gradients or glow.

## Visual direction
- **Neutrals**: warm stone (oklch), tinted slightly toward the brand so nothing is cold gray. Dark twin is a first-class citizen (warm near-black, borders ≤ 15% white, brighter status hues).
- **Accent**: emerald = *verified*. It is the single semantic accent, reserved for truth states (verified deploy, passing checks, live status). One emerald, budgeted — not everywhere.
- **Typography**: Figtree = body/UI (primary face); Oxanium = display/wordmark only (sparingly, for the brand and big page titles); JetBrains Mono = code, IDs, hashes, timestamps, and the log viewer. Clear type roles, never mix display weight into body copy.
- **Surfaces**: flat data layer. Hairline borders, quiet fills. Heavy cards are for **overlays only** (dialogs). Deployments are row-lists, not tables. No nested cards.
- **Status grammar**: a dot + label. Solid = live, empty = idle, pulsing (no spinner) = building, plus distinct hues per state. Every status has color *and* text so it is never color-only.
- **Motion**: 120–200ms, ease-out/expo, transform+opacity only. Page-load staggers over scattered micro-animations. Respect `prefers-reduced-motion`.
- **Empty states teach**: named next action + the command to copy. Never "Nothing here."
- **UI copy**: verbs + nouns (`Create project`, `Roll back`), verdict labels (`Live`, `Superseded`, `Failed`), errors say what happened *and* what to do.

## Hard rules (anti-AI-slop)
- No purple/blue gradients, no glassmorphism, no glowing accents, no emoji icons.
- No hero-metric-template layouts (big number + gradient). Metrics are typographic, not decorative.
- No identical rounded-card grids. When cards are used, vary rhythm.
- One accent color (emerald) for verification. Everything else from the stone ramp + semantic hues (amber warn, red danger).
- No `#000`/`#fff`; every surface is tinted. No gradient text anywhere.
- Icons are phosphor only (never lucide/hugeicons).
