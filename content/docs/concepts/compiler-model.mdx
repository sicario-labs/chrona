# The Compiler Model for Documentation

How Chrona applies compiler architecture principles to software documentation.

---

## Documentation as Typed Code

Traditional documentation tooling treats documentation as static presentation markup (HTML, CSS, markdown parsing). In contrast, Chrona treats documentation as a **high-level programming language of assertions**:

```text
Markdown / MDX
      │
      ▼ (Lexing & Parsing)
   Claim IR
      │
      ▼ (Type Checking / AST Referee)
Evidence Resolution
      │
      ▼ (Diagnostic Rules Engine)
Verification Result & Actionable Diagnostics
```

---

## Compilation Phases

1. **Claim Extraction**: The parser traverses documentation ASTs, identifying statements about exported functions, parameters, return types, and code snippets.
2. **Ground Truth Indexing**: Rust-powered `oxc` AST parsers scan the TypeScript/JavaScript source code to build an in-memory symbol table.
3. **Referee Matching**: The Truth Referee checks each Claim IR object against the corresponding AST entry.
4. **Diagnostic Emission**: Discrepancies generate typed `DOC-xxx` compiler diagnostics with exact file/line spans and suggested fixes.
