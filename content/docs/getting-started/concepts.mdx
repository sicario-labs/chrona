# Core Concepts

Chrona treats software documentation not as unstructured narrative prose, but as a collection of **epistemic assertions about code**.

---

## 1. Documentation Claims

A **Claim** is an explicit assertion made within documentation about your software. Chrona categorizes claims into specific types:

| Claim Type | Example | Verification Method |
|---|---|---|
| `symbol` | "`createRouter` is exported from the package" | AST export index lookup |
| `signature` | "`createRouter()` returns a `RouterContext`" | Function return type analysis |
| `parameter` | "`addRoute(router, method, path, handler)` accepts 4 args" | Parameter list & optionality matching |
| `example` | `import { DocumentationVerifier } from '@chrona/engine'` | Sandboxed compilation & static analysis |
| `deprecation` | "`legacyMethod` is deprecated" | JSDoc `@deprecated` tag verification |

---

## 2. Claim Intermediate Representation (Claim IR)

During compilation, Chrona's `ClaimExtractor` scans Markdown, MDX, and docstrings to convert prose into structured `Claim` objects:

```json
{
  "id": "claim_8f32a1",
  "type": "parameter",
  "subject": "createRouter",
  "source": {
    "file": "content/docs/api-reference.mdx",
    "line": 40,
    "text": "createRouter({ routes })"
  },
  "status": "contradicted"
}
```

---

## 3. AST Ground Truth Referee

Chrona uses the high-performance `oxc` Rust parser to inspect your TypeScript/JavaScript source code in single-pass memory:
- Traverses typed AST nodes (`FunctionDeclaration`, `TSInterfaceDeclaration`, `VariableDeclaration`).
- Computes span offsets, parameter types, default values, and JSDoc tags.
- Discovers symbol re-exports and module aliasing.

---

## 4. The Epistemic Truth Graph

Chrona connects AST facts with documentation claims through typed relational edges:
- `IMPLEMENTED_BY`: Links a symbol to its source file and line.
- `DOCUMENTED_BY`: Links a symbol to documentation pages and lines where it is referenced.
- `USED_IN`: Links a symbol to verified code examples.
- `EXPORTED_FROM`: Tracks module re-export chains.
- `CHANGED_BY`: Links symbols and claims to Git commit hashes that altered their signatures.

---

## 5. The Epistemic Contract (Provenance)

Every conclusion Chrona reaches answers six fundamental questions:
1. **What?** The subject symbol or claim being evaluated.
2. **Where?** The source file and documentation line numbers.
3. **When?** The timestamp and Git commit hash when verification was performed.
4. **Why?** The exact AST reason why the assertion is verified or contradicted.
5. **How sure?** The epistemic confidence score backed by multi-layered evidence.
6. **What changed?** Any downstream documentation claims affected by recent code changes.
