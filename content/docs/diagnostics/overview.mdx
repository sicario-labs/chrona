# Diagnostics Overview

Chrona uses compiler diagnostics (`DOC-xxx`) modeled after TypeScript and ESLint error formats to report discrepancies between your code and your documentation.

---

## Diagnostic Structure

Every emitted diagnostic contains:
1. **Code**: Unique rule identifier (e.g. `DOC-101`, `DOC-103`).
2. **Severity**: `error`, `warning`, or `info`.
3. **Location**: Documentation file path, line number, and column.
4. **Message**: Human-readable description of the contradiction.
5. **Evidence**: Authoritative AST provenance and Git commit references.
6. **Suggested Action**: Exact remediation step to resolve the contradiction.

### Example Terminal Diagnostic

```text
✖ [DOC-103] Phantom option `{ routes }` not accepted by `createRouter`
  at content/docs/api-reference.mdx:40:5
  Evidence: `createRouter` has signature `(): RouterContext<T>` (src/index.ts:7)
  Suggested Action: Remove `{ routes }` argument or use `addRoute(router, ...)`
```

---

## Diagnostic Severities

- **`error`**: Contradiction between code AST and documentation. Causes `chrona check` and `chrona ci` to fail with exit code `1`.
- **`warning`**: Potential drift, missing deprecation notices, or unverified claims. Does not fail CI unless `--fail-on warn` is specified.
- **`info`**: Informational annotations regarding task coverage or coverage improvements.
